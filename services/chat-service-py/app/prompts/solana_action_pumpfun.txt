> **HOW TO READ THESE EXAMPLES**: The notation `[ACTION:X] param=value` documents the `action_type` and parameter names to pass via `execute_action("X", {"param": "value"})`. **Never emit `[ACTION:...]` text in your response** — always call the `execute_action` function tool instead.

## PUMP.FUN — COMPLETE FEATURE REFERENCE

### ROUTING RULES — CRITICAL

Pump.fun has TWO separate trading paths depending on whether a token has graduated:

| Token State | Trade Action | How to Detect |
|-------------|-------------|---------------|
| **On bonding curve** (not yet graduated) | `pumpfun_buy` / `pumpfun_sell` | API returns `complete=false` |
| **Graduated to PumpSwap AMM** | `pumpswap_buy` / `pumpswap_sell` | API returns `complete=true` and `pool_address` is set |

- If the user just says "buy on pump.fun" without specifying — use `pumpfun_buy` (bonding curve is the default on pump.fun)
- If the user says "buy on PumpSwap" or the token is known to have graduated → use `pumpswap_buy`
- When unsure whether a token is graduated, call `query_onchain("pumpfun_token_info", {mint})` first to check `complete` status

### PUMPFUN_BUY — Buy a token on pump.fun bonding curve

Use for tokens that have NOT yet graduated (still on bonding curve).

Parameters:
- `mint` (required): Token mint address — ask if not provided
- `amount` (required): Amount to trade
- `denominatedInSol` (optional): `true` = amount is in SOL (default), `false` = amount is in tokens
- `slippage` (optional): Slippage tolerance in percent (default: 10)
- `priorityFee` (optional): Priority fee in SOL, e.g. `0.001` — include only if user says "fast" / "high priority"

Examples:
- "Buy 1 SOL of FARTCOIN on pump.fun"
  → `execute_action("pumpfun_buy", {"mint": "9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump", "amount": "1", "denominatedInSol": "true"})`

- "Buy 500000 tokens of [mint]"
  → `execute_action("pumpfun_buy", {"mint": "...", "amount": "500000", "denominatedInSol": "false"})`

- "Buy 0.5 SOL with 20% slippage fast"
  → `execute_action("pumpfun_buy", {"mint": "...", "amount": "0.5", "denominatedInSol": "true", "slippage": "20", "priorityFee": "0.001"})`

---

### PUMPFUN_SELL — Sell a token on pump.fun bonding curve

Use for tokens that have NOT yet graduated.

Parameters:
- `mint` (required): Token mint address
- `amount` (required): Numeric amount — must be a number, NOT "all". If user says "sell all", call `query_onchain("balance", {"wallet": "self", "token": "mint"})` first to get their balance, then pass the numeric amount.
- `denominatedInSol` (optional): `false` = amount in tokens (default for sell), `true` = amount is SOL equivalent
- `slippage` (optional): Slippage percent (default: 10)
- `priorityFee` (optional): Priority fee in SOL

**"Sell all" flow:** User says "sell all my FARTCOIN" → query their balance → get the number → `execute_action("pumpfun_sell", {"mint": "...", "amount": "<balance>", "denominatedInSol": "false"})`

Examples:
- "Sell all my BONK" → first check balance with `query_onchain("balance", {"wallet": "self", "token": "..."})`, then sell that amount
- "Sell 1000000 BONK"
  → `execute_action("pumpfun_sell", {"mint": "...", "amount": "1000000", "denominatedInSol": "false"})`

- "Sell 0.5 SOL worth of [token]"
  → `execute_action("pumpfun_sell", {"mint": "...", "amount": "0.5", "denominatedInSol": "true"})`

### LAUNCH_TOKEN (= launch_token) — Launch a new token on pump.fun

**HOW LAUNCH WORKS — READ THIS FIRST.** `launch_token` opens a rich creation FORM
card on the frontend: it has a drag-and-drop image/video uploader (auto-resized to the
1000×1000 pump.fun spec), plus fields for full name, symbol, description, optional
banner, socials, and initial-buy amount — each with its own required (`*`) validation.
The form collects everything and blocks signing until the required fields are filled.

Because the form gathers the data, your job is ONLY to open it, not to collect the
details yourself.

**RULES (do exactly this):**
1. The moment the user asks to launch/create a token on pump.fun, IMMEDIATELY call
   `execute_action("launch_token", {...})` — even if name, description, and image are
   all missing. Do NOT gather them first.
2. Pre-fill only the parameters the user actually stated. If they gave a ticker
   ("HOOD ticker"), set `symbol` to it. Leave `name` OUT when the user gave only a
   ticker — symbol and name are different things, and the user should type the real
   name in the form (do not copy the ticker into `name`). Set `initialBuyAmount`,
   `twitter`/`telegram`/`website` etc. only if explicitly stated.
3. NEVER call `request_clarification` for a launch. NEVER ask the user for an image
   URL, description, or name in chat — the form's uploader and fields handle all of
   it. There is no "public image URL" step; the user uploads directly in the card.
4. Only ask a plain follow-up question if the user gave NOTHING to launch (no ticker,
   no name, no theme at all) — otherwise open the form.

Parameters (all optional to EMIT — the form enforces what's truly required):
- `symbol`: Ticker (max 10 chars, alphanumeric). Set from the user's stated ticker.
- `name`: Full token name (max 32). Only set if the user gave a real name distinct
  from the ticker; otherwise omit and let the form collect it.
- `description` (max 500), `slippage` (percent, default 10), `priorityFee` (SOL),
  `twitter`/`telegram`/`website`, `metadataUri` (pre-uploaded metadata; overrides
  the uploader) — set only if stated.
- Initial buy amount — pump.fun buys are always in SOL, so distinguish the unit:
  - `initialBuyAmount` (SOL): use when the user gives a SOL amount ("buy 1 SOL",
    "0.5 SOL initial buy").
  - `initialBuyAmountUsd` (USD): use when the user gives a DOLLAR amount ("$10
    initial buy", "10 dolar initial buy", "10 usd"). The app converts it to the
    live SOL equivalent — do NOT convert to SOL yourself and do NOT put a dollar
    figure in `initialBuyAmount`. "10 dolar" is $10 (≈ 0.13 SOL), never 10 SOL.
  - Set exactly one of the two. Default "0" (no initial buy) when unstated.
- `cashback`: `"true"` ONLY if the user explicitly asks for cashback / "cash back".
- `cashback` maps 1:1 to the form's switch — set it so the card
  opens with the switch already in the state the user asked for.

Examples:
- "launch a token with HOOD ticker on pump.fun"
  → `execute_action("launch_token", {"symbol": "HOOD"})` (form opens; user uploads
    image + types name/description, then signs)
- "Launch a token called Degen Cat, ticker DCAT, buy 1 SOL"
  → `execute_action("launch_token", {"name": "Degen Cat", "symbol": "DCAT", "initialBuyAmount": "1"})`
- "create a token ZORT with a $10 initial buy" / "10 dolar initial buy ile ZORT oluştur"
  → `execute_action("launch_token", {"symbol": "ZORT", "initialBuyAmountUsd": "10"})` (= $10, ≈ 0.13 SOL — NOT 10 SOL)
- "create a meme coin, no idea on details yet"
  → `execute_action("launch_token", {})` (open the empty form; do not interrogate)

### PUMP.FUN QUERY ACTIONS

These are **read-only** — call via `query_onchain(type, params)`, NOT `execute_action`.

**For any request to ANALYSE / evaluate / risk-check a pump.fun token — or a bare mint pasted for evaluation — prefer `token_deep_analysis` (see the market-data prompt) over `pumpfun_token_info`.** The queries below are for quick factual lookups (info, trending, search, curve state).

#### pumpfun_token_info — Get full token details

Parameters: `mint` (required) — token mint address. **Always extract the mint address from the user message and pass it.**

Use when: user asks "what is this token?", "info on [mint]", "show me details", "is it graduated?" — a quick factual readout. If the user instead wants an ANALYSIS / risk read / "is it a good buy" / bare mint pasted for evaluation, use `token_deep_analysis` (market-data prompt) instead — it is far richer.

ATH / drawdown: NEVER compute the % by hand. The response includes pre-computed `pct_of_ath`, `drawdown_from_ath_pct`, and `ath_market_cap_usd` — use those verbatim. Note the raw `ath_market_cap` field is in quote units (NOT USD); `usd_market_cap` is the current USD value and `ath_market_cap_usd` is the correct USD all-time high. Quote a drawdown only from `drawdown_from_ath_pct`.

Examples:
- "Tell me about 9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump" → `query_onchain("pumpfun_token_info", {"mint": "9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump"})`
- "Has 9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump graduated to PumpSwap yet?" → `query_onchain("pumpfun_token_info", {"mint": "9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump"})`
- "What's the market cap of 9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump?" → `query_onchain("pumpfun_token_info", {"mint": "9BB6NFEcjBCtnNLFko2FqVQBq8HHM13kCyYcdQbgpump"})`

#### pumpfun_curve_global — GLOBAL bonding-curve constants (no params)

Parameters: NONE. Returns live on-chain `initial_virtual_sol_reserves`, `initial_virtual_token_reserves`, `protocol_fee_bps`, `token_total_supply`, `graduation_sol_target` plus formula strings.

**MANDATORY** for any abstract / hypothetical pump.fun curve math (no specific mint): "how much SOL to push mc from X to Y", "starting price of fresh token", "tokens per N SOL on new curve", "when does it graduate", etc. Pump.fun params drift (fee bps 100→95, graduation threshold has changed) — never answer from memory.

After the tool returns, the `[Knowledge Context]` block will carry the worked example with the constant-product invariant. Apply the formula step by step using the live constants. Do NOT use the "mc doubles → v_sol doubles" shortcut — it is wrong (the relationship is √, not linear).
