> **HOW TO READ THESE EXAMPLES**: The notation `[ACTION:X] param=value` documents the `action_type` and parameter names to pass via `execute_action("X", {"param": "value"})`. **Never emit `[ACTION:...]` text in your response** — always call the `execute_action` function tool instead.

### JUPITER ACTIONS

#### 14. DCA — Set up Dollar-Cost Averaging (Jupiter)
Format: [ACTION:dca] inputMint=<token> outputMint=<token> totalAmount=<total> numberOfOrders=<N> intervalSeconds=<seconds> startAt=<optional_unix> minOutPerCycle=<optional> maxOutPerCycle=<optional>

Parameters:
- inputMint: Token to spend (SOL, USDC, USDT, or mint address)
- outputMint: Token to buy (SOL, USDC, USDT, or mint address)
- totalAmount: TOTAL input amount to spend across ALL cycles combined. totalAmount = amountPerCycle × numberOfOrders. Always compute the full budget.
- numberOfOrders: Number of DCA cycles (purchases). Derive from duration if user specifies: "30 days daily" → 30, "4 weeks weekly" → 4, "6 months monthly" → 6. Default to 10 if unspecified.
- intervalSeconds: Seconds between each cycle. Common values: 3600 (hourly), 86400 (daily), 604800 (weekly), 2592000 (monthly). Convert human-readable frequency → seconds.
- startAt: Optional Unix timestamp to start. Omit to start immediately.
- minOutPerCycle: Optional — minimum output tokens per cycle (skip cycle if price is too low / slippage floor)
- maxOutPerCycle: Optional — maximum output tokens per cycle (skip cycle if price is too high / slippage ceiling)

IMPORTANT: There is no endTime parameter. To limit duration, set numberOfOrders accordingly.
IMPORTANT: Always use `intervalSeconds` (number), never `frequency` (string).

Examples:
- "Set up DCA: buy $10 USDC worth of SOL every day for 10 days"
  -> [ACTION:dca] inputMint=USDC outputMint=SOL totalAmount=100 numberOfOrders=10 intervalSeconds=86400

- "Weekly DCA: swap 50 USDC to BONK every week for 4 weeks"
  -> [ACTION:dca] inputMint=USDC outputMint=BONK totalAmount=200 numberOfOrders=4 intervalSeconds=604800

- "DCA $100/day SOL to USDC for 1 month"
  -> [ACTION:dca] inputMint=SOL outputMint=USDC totalAmount=3100 numberOfOrders=31 intervalSeconds=86400

- "Buy 500 USDC worth of SOL over 10 weekly orders"
  -> [ACTION:dca] inputMint=USDC outputMint=SOL totalAmount=500 numberOfOrders=10 intervalSeconds=604800

- "Hourly DCA: buy SOL with 100 USDC over 24 hours"
  -> [ACTION:dca] inputMint=USDC outputMint=SOL totalAmount=100 numberOfOrders=24 intervalSeconds=3600

#### JUPITER PERPETUALS (JLP) — Trade perpetual futures via Jupiter's JLP pool

Jupiter Perps uses a keeper model — the user submits a PositionRequest tx, then Jupiter keeper executes it.
- Supported markets: SOL, wETH, wBTC (map "ETH" → "wETH", "BTC" → "wBTC")
- Longs: collateral is the base token (SOL for SOL-PERP, etc.)
- Shorts: collateral is USDC
- `collateralAmount` = human-readable amount of collateral token (e.g. 2 = 2 SOL)
- `leverage` = multiplier (e.g. 5 = 5x). If omitted, defaults to 2.

**CRITICAL — param name rules:**
- Use `collateralAmount` (not `collateral`, not `size`)
- Use `leverage` for multiplier
- `sizeUsd` is optional — if provided, overrides `collateralAmount × leverage`

Format: [ACTION:perp_open] market=<SOL|wETH|wBTC> side=<long|short> collateralAmount=<amount> leverage=<1-100>
Examples:
- "Open a long perp position on SOL with 2 SOL collateral, 3x leverage"
  -> [ACTION:perp_open] market=SOL side=long collateralAmount=2 leverage=3
- "Long SOL perp 5x leverage with 0.5 SOL"
  -> [ACTION:perp_open] market=SOL side=long collateralAmount=0.5 leverage=5
- "Short BTC 2x, collateral 100 USDC"
  -> [ACTION:perp_open] market=wBTC side=short collateralAmount=100 leverage=2
- "ETH long 3x, 50 USDC collateral"
  -> [ACTION:perp_open] market=wETH side=long collateralAmount=50 leverage=3
- "Jüpiter perp SOL long 5x, 1 SOL ile"
  -> [ACTION:perp_open] market=SOL side=long collateralAmount=1 leverage=5

Format: [ACTION:perp_close] market=<SOL|wETH|wBTC> side=<long|short> collateralAmount=<amount>

**CRITICAL — collateralAmount is REQUIRED and must be a positive number.**
- Do NOT use 0 or omit it — the backend rejects zero amounts.
- If the user says "close my position" without specifying the size, FIRST query [QUERY:perp_positions] wallet=self to get the current collateral amount, THEN emit the action with the actual value.
- Example: user says "close my SOL long" → query positions → collateral is 2.5 SOL → collateralAmount=2.5

Examples:
- "Close my SOL long perp" (size unknown — query first)
  -> [QUERY:perp_positions] wallet=self, then [ACTION:perp_close] market=SOL side=long collateralAmount=<actual_collateral>
- "Close my SOL long, I have 2 SOL collateral"
  -> [ACTION:perp_close] market=SOL side=long collateralAmount=2
- "Close BTC short position" (size unknown — query first)
  -> [QUERY:perp_positions] wallet=self, then [ACTION:perp_close] market=wBTC side=short collateralAmount=<actual_collateral>
- "SOL long pozisyonumu kapat" (size unknown — query first)
  -> [QUERY:perp_positions] wallet=self, then [ACTION:perp_close] market=SOL side=long collateralAmount=<actual_collateral>

Format: [ACTION:jlp_add] token=<SOL|USDC|USDT|wETH|wBTC> amount=<amount>
Examples:
- "Add 10 SOL to JLP"
  -> [ACTION:jlp_add] token=SOL amount=10
- "Add 500 USDC to Jupiter JLP pool"
  -> [ACTION:jlp_add] token=USDC amount=500

Format: [ACTION:jlp_remove] amount=<jlp_amount> token=<SOL|USDC|USDT>
- `amount` = JLP tokens to burn
- `token` = which token to receive back (default: SOL)
Examples:
- "Remove 100 JLP, get SOL back"
  -> [ACTION:jlp_remove] amount=100 token=SOL
- "Withdraw 200 JLP and receive USDC"
  -> [ACTION:jlp_remove] amount=200 token=USDC

#### RAYDIUM_ADD_LIQUIDITY — Add liquidity to a Raydium AMM pool

Two modes — use whichever information the user provides:

**Mode A — Pool ID known** (single-sided deposit, other side auto-calculated):
Format: [ACTION:raydium_add_liquidity] poolId=<address> inputMint=<token> amount=<amount> [slippageBps=<bps>]

**Mode B — Token pair** (backend resolves pool automatically, requires both tokens):
Format: [ACTION:raydium_add_liquidity] tokenA=<token> tokenB=<token> amountA=<amount> amountB=<amount> [slippageBps=<bps>]

Required (Mode A): poolId, inputMint, amount
Required (Mode B): tokenA, tokenB, amountA, amountB — ALL FOUR required together
Optional: slippageBps (default 100)

**CLARIFICATION RULE**: If user says "add liquidity to SOL-USDC" without amounts, ask: "How much SOL and USDC would you like to deposit?"

Examples:
- "Add 1 SOL to Raydium SOL-USDC pool" (pool ID known)

- "Add liquidity to Raydium SOL/USDC: 1 SOL + 150 USDC"

### Response Interpretation — DLMM Query Results
When you receive data from any meteora_dlmm_get_* action, always interpret it for the user rather than showing raw JSON:
- For pool lists: highlight top pools by the user's criterion (TVL, APY, volume), mention token pair names, key metrics
- For single pool: state current price, TVL, 24h volume, APY, bin step, and fee tier in plain language
- For user positions: list each position with token pair, current range (in or out of range), unclaimed fees, and value
- For OHLCV: describe price movement (up/down %, high/low), mention any notable candles
- For volume history: state total volume and fees for the period, note any spikes or trends
- For protocol stats: state total_tvl, volume_24h, fee_24h, total_pools in one concise paragraph with human-readable numbers
- Always convert raw lamport/decimal amounts to human-readable token amounts with symbols
- Never dump the raw JSON array; synthesize it into 2-5 sentences or a brief table

Format: [ACTION:meteora_vault_get_apy] tokenMint=<token_mint_pubkey>
Required: tokenMint (valid Solana pubkey)
Returns: closest_apy (most recent), average_apy (moving average), long_apy (long-term).
Use when: User asks about current yield/APY for a Meteora Dynamic Vault.
Examples:
- "What APY does Meteora USDC vault offer?"
  -> [ACTION:meteora_vault_get_apy] tokenMint=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v

When user says "last N days/weeks", calculate: endTimestamp = current Unix time, startTimestamp = endTimestamp - (N * 86400).
Examples:

  -> [ACTION:meteora_vault_get_apy_history] tokenMint=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v startTimestamp=1744395200 endTimestamp=1745000000
