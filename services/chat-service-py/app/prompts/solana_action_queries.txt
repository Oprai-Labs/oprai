> **HOW TO READ THESE EXAMPLES**: The notation `[QUERY:X] param=value` documents the `query_type` and parameter names to pass via `query_onchain("X", {"param": "value"})`. **Never emit `[QUERY:...]` text in your response** — always call the `query_onchain` function tool instead.

---

#### ⚠ ROUTING DISAMBIGUATION — READ BEFORE PICKING A QUERY TYPE

**LST native staking APR/APY** (jitoSOL, mSOL, jupSOL, bSOL, INF, stSOL, etc.)
→ Always `query_onchain("yield", {"token": "SOL", "category": "liquid_staking"})`
→ **Never** use pool, dex_token, birdeye, token_info, or `jup_lend_markets` for this. `jup_lend_markets` returns lending/borrowing rates on Jupiter Lend, not native staking APR.
→ "jitoSOL APR", "mSOL yield", "how much do I earn staking SOL", "value that grows over time via staking", "staking return" all route here.

**LP / liquidity pool APR**
→ Use pool queries (meteora_dlmm_*, kamino_vaults, etc.) only when the user explicitly says "pool", "liquidity", "LP", or names a specific pair like "SOL-USDC pool".
→ Do NOT route here for generic LST APR questions.

**Token price movement** ("how much did jitoSOL go up?")
→ `query_onchain("price", ...)` — tracks market price, not staking yield.

#### QUERY: yield — Best yield opportunities AND liquid staking APR
Format: [QUERY:yield] token=<optional> minApy=<optional> protocol=<optional> category=<liquid_staking|lending|optional>

**CRITICAL**: Any question about the APR/APY of jitoSOL, mSOL, jupSOL, bSOL, INF, or any LST
as a staking asset (not as an LP pair) MUST use this query with category="liquid_staking".
Do NOT use dex_token, birdeye_token_overview, or pool queries for LST staking APR — those
return LP yields, not the native staking rate.

Examples:
- "Where can I earn yield?" → query_onchain("yield", {})
- "Best SOL staking rates" → query_onchain("yield", {"token": "SOL"})
- "APY over 10%?" → query_onchain("yield", {"minApy": "10"})

#### QUERY: limit_orders — View Jupiter limit orders (open or history)
Format: [QUERY:limit_orders] wallet=<address|self> status=<open|history>

- status=open (default): show currently open limit orders
- status=history: show filled or cancelled orders

Use this when the user asks to SEE / LIST / VIEW their limit orders. Do NOT use this when the user wants to CREATE a new limit order (use ACTION:limit_order for that).

Examples:
- "Show my limit orders" → query_onchain("limit_orders", {"wallet": "self"})
- "What limit orders do I have?" → query_onchain("limit_orders", {"wallet": "self", "status": "open"})
- "My open orders on Jupiter" → query_onchain("limit_orders", {"wallet": "self"})
- "Show my filled/completed orders" → query_onchain("limit_orders", {"wallet": "self", "status": "history"})
- "Show my order history" → query_onchain("limit_orders", {"wallet": "self", "status": "history"})
