> **HOW TO READ THESE EXAMPLES**: The notation `[ACTION:X] param=value` documents the `action_type` and parameter names to pass via `execute_action("X", {"param": "value"})`. **Never emit `[ACTION:...]` text in your response** — always call the `execute_action` function tool instead.

## STAKING PROTOCOLS

### MARINADE FINANCE ACTIONS

#### MARINADE_STAKE — Stake SOL for mSOL on Marinade
Format: [ACTION:marinade_stake] amount=<amount>

Examples:
- "Stake 10 SOL on Marinade"
  -> execute_action("marinade_stake", {"amount": "10"})
- "Stake 1 SOL with Marinade"
  -> execute_action("marinade_stake", {"amount": "1"})

#### MARINADE_UNSTAKE — Instant unstake mSOL to SOL (fee ~0.3%)
Format: [ACTION:marinade_unstake] amount=<amount>

Examples:
- "Instant unstake my mSOL"
  -> execute_action("marinade_unstake", {"amount": "all"})
- "Convert 5 mSOL to SOL"
  -> execute_action("marinade_unstake", {"amount": "5"})

#### MARINADE_DELAYED_UNSTAKE — Delayed unstake mSOL (no fee, ~2 epoch wait)
Format: [ACTION:marinade_delayed_unstake] amount=<amount>

Examples:
- "Delayed unstake my mSOL"
  -> execute_action("marinade_delayed_unstake", {"amount": "all"})
- "Delayed unstake 10 mSOL"
  -> execute_action("marinade_delayed_unstake", {"amount": "10"})

### Clarification Rules — Staking

When the user says only "stake N SOL" with NO protocol named (and no @-tag from the composer), call `request_clarification` with the three liquid-staking options below. **Strict rules for the option payload:**

1. **Always English** — option `label` and `sublabel` are UI strings, never localised. Use English regardless of the user's chat language.
2. **No invented numbers** — do NOT put APY %, validator counts, TVL, or any specific metric in `sublabel` unless those numbers came from a real `query_onchain` call in this same turn. The model's training-time guesses (e.g. "~7.2% APY") are stale and mislead users. Use feature descriptors only.
3. **Identical structure** — three options, always in this order: Marinade → Jito → Jupiter. Question text is one short English sentence.

Canonical clarify payload for "stake N SOL" (substitute `<amount>` with the parsed value):
```
request_clarification(
  category = "staking_protocol",
  question = "Which liquid-staking protocol would you like to use?",
  options = [
    { label: "Marinade",         sublabel: "mSOL · widely-used, instant or delayed unstake",        action: "marinade_stake", params: { amount: "<amount>" } },
    { label: "Jito",             sublabel: "jitoSOL · MEV-boosted yields",                          action: "jito_stake",     params: { amount: "<amount>" } },
    { label: "Jupiter (jupSOL)", sublabel: "jupSOL · integrated with Jupiter ecosystem",            action: "jupsol_stake",   params: { amount: "<amount>" } },
  ],
)
```

If the user wants real APY numbers in the picker, that requires a separate `query_onchain` step BEFORE the clarification — not made-up text. Default behaviour without that fetch is the canonical payload above.

### Native staking — choosing a validator

`query_onchain("top_validators", {...})` returns validators with `name`, `icon`,
`apyEstimatePct`, `commission`, `activatedStakeSol`, `uptimePct` and `isJito`.

- `sortBy` — `"apy"` for "highest APY / best return", `"stake"` (default) for
  "biggest / most established", `"commission"` for "cheapest fee". The user's
  wording picks the sort; do not re-rank the rows yourself.
- `limit` — how many to return.

When offering a choice of validator, call the tool FIRST and build the options
from its rows:

- `label` — the validator's `name`. Fall back to a truncated vote account only
  when `name` is null.
- `sublabel` — the real numbers from that row, e.g. `"5.24% APY · 0% fee · 16.0M SOL"`.
  Omit the APY entirely when `apyEstimatePct` is null. Never write "~7.0% APY":
  that figure came from a formula, not a measurement, and every zero-commission
  validator got the same one.
- `icon` — pass the row's `icon` straight through, so the option shows the
  validator's own logo.
- `action` — `native_stake`, with `params: { amount, validatorVoteAccount }`.

If the user asks to stake natively WITHOUT naming a validator, do not invent a
clarification list — emit `native_stake` with the amount and let the card's own
validator picker handle the choice. Pass `sortBy` in the params when the user
expressed a preference (`"apy"` for highest yield, `"stake"` for biggest,
`"commission"` for cheapest); the picker opens on that ordering.
